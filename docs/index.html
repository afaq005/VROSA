VROSA00:00:01

Say what you want. Leave how to the robot.

Mobile robots deployed in manufacturing, logistics, inspection, and service settings are largely confined to pre-programmed tasks — adapting behaviour to a new instruction usually means engineering time, reprogramming, and redeployment. VROSA is a vision-language agent framework, built on ROS 2, that lets an operator issue natural language commands directly: an LLM planner selects from a constrained tool registry rather than generating raw motor commands, keeping semantic reasoning and physical execution separate for safety and auditability.

The system pairs a hot-swappable vision-language model (VLM) backend — cloud, local, or remote — with a camera-first perception pipeline (YOLO + GroundingDINO + Depth Anything V2) that estimates object distance without requiring LiDAR. A closed-loop plan–execute–recheck navigation cycle alternates sparse VLM direction queries with dense, sensor-driven motion steps.

NAVplan_execute_recheck

One VLM call per leg. Every step in between is sensor-only.

navigate_to_object runs a plan–execute–recheck loop: a single VLM call ("scout") returns a coarse direction and distance; the robot then drives a portion of that estimated distance in small sensor-checked sub-steps — depth and, when available, LiDAR — with no further VLM calls until the leg completes or an obstacle intervenes. Real hardware trials average roughly one VLM query per metre travelled, not per motion step.

PERCsensor_fusion

LiDAR when it's there. A camera when it isn't.

Every detection's distance is resolved by a priority function over whatever sensing channels are actually available on the platform — a real constraint, since the AgileX Scout 2.0 hardware trials run entirely camera-only. LiDAR (when present) projects each bounding box's angular span onto the point cloud via bearing angle; without it, a depth-map centre-crop with an adaptive percentile — biased toward the nearest surface up close, more median-like at range — takes over. No architecture change is required to move between the two.

01

YOLO

Fixed-class detection, ~15 fps GPU fast loop. Low latency, bounded vocabulary.

02

GroundingDINO

Open-vocabulary grounding, ~1 fps CPU slow loop. Free-form text prompts for arbitrary objects.

03

Depth Anything V2

Metric monocular depth. Camera-only distance fallback when LiDAR is unavailable.

04

LiDAR (optional)

Bearing-angle bbox projection, 20th-percentile return. Primary channel when present.

HWscout_2.0 · jbnu_campus

Off the sim floor, onto a Korean university campus.

Physical trials ran on an AgileX Scout 2.0 four-wheel skid-steer UGV with a Jetson AGX Orin 64GB running all perception and agent computation onboard — camera-only, no LiDAR. Twenty-four navigation trials spanned three outdoor sessions (midday sun and glare, evening, early morning), targets from 0.5–23.2 m, cluttered e-bike/scooter zones, a Korean-text no-parking sign commanded in English, and a person who moved mid-navigation.

VLMbackend_manager

Format compliance matters more than description quality.

Three VLM backends were compared under identical fused-mode conditions (50 sim trials each). Claude Sonnet, LLaVA V5, and Phi-4 Base landed within a few points of each other on navigation success — the differences aren't statistically significant at this sample size. What did separate them was direction-query format compliance, which tracked completion time and attempt count far more tightly than raw success rate.

Where it breaks

SENSOR MODALITY DEPENDENCY

With depth, YOLO, and LiDAR all disabled, VLM-only distance estimation is unreliable enough to prevent arrival confirmation. At least one sensing channel is required.

SMALL OBJECTS + DIRECT GLARE

The single confirmed hardware failure: a cola can on a white line under direct midday sun. Same target succeeded in shade. High-contrast glare, not low light, is the issue.

REFLECTIVE SURFACES

Metallic objects produce larger depth errors and can trigger early (safe, but imprecise) safety stops from shortened LiDAR returns in simulation.

VLM DIRECTION INSTABILITY

Visually symmetric scenes (matching shelves either side of a corridor) can cause the VLM to alternate direction labels across queries.

Run it yourself

Robot-agnostic by design — porting between the simulated Nova Carter and the physical Scout 2.0 required changing only ROS 2 topic constants, with zero changes to agent, tool, perception, or motion code.
